# Database

Schema: `database/schema.sql` (MySQL 8.0.16+ / MariaDB 10.4+, InnoDB, utf8mb4).

## Tables

| Table | Key columns | Notes |
|---|---|---|
| `User` | `Uid`, `email` (unique), `Password` (bcrypt), `Role` (`user`/`admin`), `reset_token` (SHA-256 hex), `token_expires` | |
| `Expense` | `Eid`, `Uid` (NOT NULL, FK), `category`, `amount` (> 0), `date`, `description`, `Payment_Method` | Index on `(Uid, date)` serves every report and the ML service |
| `Budget` | `Bid`, `Uid`, `Month` (`YYYY-MM`), `Amount` (> 0) | `UNIQUE (Uid, Month)` |
| `Income` | `Iid`, `Uid`, `Month` (`YYYY-MM`), `Income` (> 0) | `UNIQUE (Uid, Month)` |
| `Query` | `Qid`, `Uid`, `Email`, `Query_type`, `Description`, `Status`, `Admin_Response`, `Response_Date` | Support requests |

All child tables use `ON DELETE CASCADE`, so deleting a user removes their data.

## Fresh install

```bash
mysql -u root -p -e "CREATE DATABASE FiscalPoint CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
mysql -u root -p FiscalPoint < database/schema.sql
mysql -u root -p FiscalPoint < database/seed_demo.sql    # optional
```

## Demo data

`database/seed_demo.sql` is generated by `python -m fiscalpoint_ml.data.seed_sql` (8 synthetic users,
24 months, ~6k expenses, incomes and budgets, plus one admin). It contains **no real personal data**.
The history ends on the generation date. Regenerate it to get fresh "current month" data:

```bash
cd ml && python -m fiscalpoint_ml.data.seed_sql --users 8 --months 24
```

## Upgrading a database created from the old `FiscalPoint.sql`

1. **Back up**: `mysqldump -u root -p FiscalPoint > backup.sql`
2. Make sure budget and income months use `YYYY-MM`. Old records that stored only a month name
   (e.g. `March`) cannot be converted automatically because the year is unknown:
   ```sql
   SELECT * FROM Budget WHERE Month NOT REGEXP '^[0-9]{4}-(0[1-9]|1[0-2])$';
   SELECT * FROM Income WHERE Month NOT REGEXP '^[0-9]{4}-(0[1-9]|1[0-2])$';
   -- fix each one, e.g. UPDATE Budget SET Month = '2025-03' WHERE Bid = 7;
   ```
3. Run `mysql -u root -p FiscalPoint < database/migrations/001_ml_overhaul.sql`.

The migration first prints what it will change, then:
* deletes orphaned or invalid expenses (NULL user, zero amount, missing date or category);
* keeps only the newest budget / income row per user and month;
* clears outstanding password-reset tokens (they were stored in plain text);
* adds NOT NULL constraints, unique keys (`email`, `Uid+Month`) and indexes.

It was tested against a database created from the original dump: 8 invalid expenses and
2 duplicate budgets were removed and all constraints applied.

## Conventions

* Dates are `DATE`; months are `CHAR(7)` `YYYY-MM`.
* Money is `DECIMAL`. PHP reads it as a string and casts it for arithmetic.
* The MySQL session timezone is set from `APP_TIMEZONE`, so `NOW()` and `CURDATE()` agree with PHP.
